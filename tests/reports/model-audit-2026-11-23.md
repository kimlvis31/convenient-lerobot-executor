## Scope and evidence

- 243 command/wizard contracts, 297 training option-parser values, 250 real training-question fields, 179 evaluation option-parser values, 153 component-scope choices and 54 terminal paths (27 models, widths 90/160) passed.
- The final code passed all 374 native regression tests and 362 Windows tests with 12 conditional skips. The original external SSD checkout is compared to the verified source after line-ending normalization and Git object checks are retained in the private verification bundle.
- Real-model samples span successive audit source snapshots. The final regression suite validates the retained implementation; every real model combination was not rerun against one final revision.
- Real tests use short episodes (usually 1–2 control steps), usually 2 training steps and a checkpoint-step-1-to-2 resume. The pi0_fast fresh training fixture uses one step before that resume. TinyVLA additionally interrupts at step 1 and resumes to 20.
- Reduced denoising counts and memory-saving training scopes/optimizers are explicit test profiles. The standard Wall-OSS Euler-step constraint is preserved. New or lightly adapted policies do not establish task performance.
- B/P denotes episodes per policy batch / parallel distinct tasks. PushT and ALOHA have one task per job. A passed forwarding contract does not prove a model fits every batch on this machine.
- TinyVLA's listed CPU is the native bridge device; its external inference worker is a separate interpreter. WALL-X's CUDA initializer uses cached public base weights and explicit identity normalization; it is separate from the trained-checkpoint CPU evaluation.
- Native dataset: the existing one-episode LIBERO fixture. Temporary PushT episode 0 is audit-owned. User data, original sources/environments and existing weights are preserved.
- Hardware: RTX 3080 Ti (11.61 GiB reported by Torch), approximately 67.3 GB system memory. Owned process trees stop at 54 GB proportional memory or a bounded model-execution window.
- Output evidence checks scripts, stage status, checkpoints, metrics and available videos. Video decoding/resource sampling was added during the audit; it does not cover every initial attempt.
- These are bounded functional samples and exhaustive checks of the presented option schemas, not real executions of every Cartesian combination of weights, data, training scope, batch, task and benchmark. Equal action dimensions do not establish matching robot semantics. The separate Gaussian Actor learner is outside the supervised training launcher.

## Shared corrections

The manager rejects unknown job keys and unavailable runtime fields, exposes model-specific loss/checkpointing controls and typed evaluation controls, keeps exact-resume configuration, and displays valid local saved training-option values. Numeric optimizer arrays and FastWAM loss/scheduler dictionaries use a validated JSON editor. GR00T native LoRA controls reach its own declared training fields. Native checkpoint tensors stage through host memory before final device placement. Parallel task copies share auxiliary weight modules as well as registered parameters; mutable buffers, queues and processors stay separate. Partial batches retain exactly the requested metrics/videos. Evaluation checks action dimensions before loading weights, without assuming equal dimensions prove equivalent robot semantics. SIGTERM follows owned-stage interruption cleanup while respecting existing signal handlers. The root run.sh only launches executor/manage.py.

Full MolmoAct2 policy checkpoints no longer download and initialize a redundant raw base policy before loading their authoritative weights. Native strict loading, processors and dataset statistics remain active. Known dense legacy exports use a temporary compatible configuration view; legacy adapter topologies still require their original loader. The documented standard LIBERO feature labels/camera map are resolved before dataset construction, and explicit or resumed labels survive native metadata setters. Unknown datasets are not assigned guessed semantics. Actual native LoRA training, exact resume and resumed-export evaluation verify this path.

Evaluation processor preflight checks local files or pinned Hub metadata before constructing a native model, preserves model-specific processor hooks and falls back to native cached behavior when metadata is unavailable. It detects the EO-1 initializer's missing processor files in an actual native API probe in 0.444 seconds without calling its model factory. It does not fabricate normalization statistics. Imported evaluation options are checked against the effective runtime catalog; CUDA automatic mixed precision is labelled explicitly. Missing processors, cuDNN backend errors and mixed input/weight types receive short actionable failure summaries with the original log link retained.

WALL-X's native constructor originally moves the float32 model to CUDA before applying its own mixed precision. The executor applies that same native precision conversion on host memory first, preserving native vocabulary initialization and weight loading. The cached native base initializer completes a CUDA rollout in 164.588 seconds with a 9,631 MiB measured peak and a decoded result video. Earlier CUDA attempts failed during placement. These profiles differ, so no controlled speedup or exact memory-saving percentage is claimed.

Two exploratory changes were not retained: skipping WALL-X covariance initialization gave no controlled overall speed benefit, and a source-matched DM05 CPU bf16 profile did not complete training within its time window. Their evidence remains in the private bundle; final defaults preserve the native initializer and do not automatically enable that unverified training profile.

Verified standard LIBERO rollouts reuse task descriptions and camera frames already present in observations. Real synchronous/asynchronous frame comparisons pass. Paired SmolVLA baseline/optimized/restored runs have identical actions and saved frames; 50 render requests become 0 and 48 task-description requests become 2. In that short profile, inference and initialization dominate; no general speedup percentage is claimed. One earlier exact-hash comparison failed before detailed trace retention; subsequent detailed and three-run comparisons match. Its cause was not established.

## Verification boundaries and cleanup

SmolVLA's combined continuation-plus-evaluation workflow selected the newly written checkpoint, completed both stages, retained scripts/logs in both result folders and counted six requested episodes. Failed attempts and the exact temporary public download revisions are retained in the private audit evidence; the public asset manifest distinguishes downloaded copies, reused original cache data and metadata-only access probes. Original source, datasets, environments, user outputs and original cached weight checksums are protected. Gated account access and hardware/robot-contract constraints are reported separately from manager defects. Cleanup completion and actual freed bytes are recorded in the final cleanup receipt; logical hard-link sizes are not reported as freed disk space.

Original LeRobot and model source files were not edited. Runtime compatibility hooks in executor child processes wrap loading, device placement and native evaluation helpers. They are restored when those contexts exit. User model weights remain unchanged; generated training checkpoints were audit-owned and disposable.

Final cleanup removed four audit-owned environments and the dedicated remote workspace after verifying a 202-file evidence archive. The last cleanup increased observed free space by 89,774,395,392 bytes (89.8 GB); earlier deletions are not added to this measurement. All five original environments remain. Original metadata (279 files), 18 weight blobs (49,554,035,160 bytes) and the original clean LeRobot revision were verified.
