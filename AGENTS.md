# Agent setup guide for convLexecutor

- Use this checkout as the working directory. It contains the executor, scripts, datasets, external adapters, and outputs. Reuse LeRobot from an installed Conda environment. Confirm the actual folders before modifying an existing installation.
- Read the English `README.md` or `README.ko.md` for the setup sequence. The verified native version is LeRobot 0.6.2, revision `145cc7ea53e5864bd5efec4e9bb70ee799e47bd8`, with LIBERO. Read the model-environment requirements in the README and check for bfloat16 support before preparing examples.
- Check the existing Conda environments first. Reuse `lerobot` and either `tinyvla_infer` or `lerobot_tinyvla` when compatible. Install the bundled TinyVLA evaluation adapter only in the native LeRobot environment, using `python -m pip install --no-deps --no-build-isolation --editable ./externals/TinyVLA/lerobot_policy_tinyvla` from this checkout. Editable installation lets `git pull` update the application and adapter together; rerun that installation once for an older copied-package setup and verify that imports resolve to this checkout.
- First-use source benchmark setup is part of the executor architecture. On Linux, a confirmed RoboTwin, LIBERO-plus, RoboCasa365, or VLABench evaluation can prepare its pinned source, dependencies, and assets through `executor/runtime_setup.py`. RoboTwin uses a separate simulator interpreter. Combined source recipes clone a compatible policy environment before making changes. Preserve the original LeRobot source, existing Conda environments, user datasets, and checkpoints. Never apply a source recipe directly to an original environment.
- Preserve the policy environment's model cache paths when preparing source runtimes. Install value-free activation hooks only in owned environments; inherit supported source variables in child memory, restore prior values on deactivation, and never serialize credential values into settings, manifests, or hooks.
- Keep preview and inventory operations read-only. A source runtime is ready only after its pinned source and required assets are verified, package checks pass, and actual rendered cameras plus one physical simulation step succeed. Save the source revisions and effective runtime environment. Reuse the same managed runtime when its requirements still match; do not silently replace explicit user settings or mask missing hardware/access conditions.
- Managed source runtimes default to this checkout's `externals/.runtimes/`; `CONVLEX_RUNTIME_CACHE` can select another absolute location. For verification, use a dedicated temporary runtime cache and output folder, test one large benchmark/model at a time, and immediately remove only those exact owned folders when finished. Retain completed archives for retries until the entire runtime passes package and physical checks, then remove its download directory when readiness is published. Never use global Docker, Conda, model-cache, or dataset cleanup to remove a test's artifacts. Preserve application dependencies that the user needs for actual use unless their removal is authorized.
- Run `python -B executor/prepare_examples.py --dry-run` before calling the same command without `--dry-run`. Preparation verifies or downloads the pinned public base weights and the selected demonstration files, then generates the two local example fixtures if needed. Existing files are checked before reuse. Preserve user-created datasets and checkpoints.
- If source checks reject an older generated example resume state, preserve user training states, valid exported models, datasets, and base weights. Stage current fixtures with `executor/prepare_examples.py --checkpoint-root <new-empty-staging-directory>` after its dry run, verify the model and a step-2-to-step-4 resume, and publish only the identified provided example requiring refresh. Update a moved generated resume fixture's `settings.json` field `train.selection` to its final `selection.json` path. Never rewrite saved trainer/loader hashes or weaken resume checks. Real training history requires its original source version for exact resume or a new run from exported weights with a fresh optimizer; generating practice fixtures is not a migration of user training history.
- Check installation with `python -B executor/manage.py --inventory`. Preview the example queue with `python -B executor/manage.py --queue scripts/example_script.py --dry-run`. For an actual smoke test, run the queue and check `status.json`, `run.py`, `script.py`, and the stage outputs. Distinguish a completed evaluation from task success.
- Keep fetched data, weights, experiment outputs and logs out of Git. Sources and attribution are in `THIRD_PARTY.md`. First-party executable scripts are AI-written and the README records that provenance.
- Keep automated checks under `tests/`, separate from runtime modules. From the project root run `python -B -m unittest discover -v`; with absolute paths use `-s <project>/tests -t <project>`. Keep machine-specific audit scripts and artifacts outside the source checkout, and remove owned temporary files after retaining the required verification evidence.
